Two agents, one job

Watch AI agents pass work to each other

Think about visiting a doctor's office. First the receptionist listens and fills in a form: what's wrong, when it started. Then they hand the form to the nurse, who reads it, decides how urgent you are, and asks about anything the form is missing.

Real AI systems often work the same way. Instead of one AI doing everything, several agents each do one job and pass the work along. That's what "multi-agent" means. On this page, two agents turn a messy bug report into a tidy one:

  • Agent 1, the Drafter — fills in a bug-report form from your words: title, description, severity, steps, device.
  • Agent 2, Triage — reads the form, decides how urgent it is (HIGH, MEDIUM or LOW), and flags what's missing.

The moment the form passes from one agent to the other is the handoff. It can go as JSON — a strict format that's checked before it's passed on — or as plain text, which nobody checks. Here, both agents follow simple rules, not real thinking, so you can see every step.

6 examples: how urgent is it?

Each example shows a bug report, the form the Drafter filled in, the handoff, and what Triage decided.

  1. Bug report: the app crashes when I upload big files

    📋 Rule-based — both agents follow simple, visible rules.
Handoff format: json

[AGENT 1: Drafter]  Received: "the app crashes when I upload big files"
[AGENT 1: Drafter]  Output →
                    {
                      "title": "The app crashes when I upload big files",
                      "description": "the app crashes when I upload big files",
                      "severity": "unknown",
                      "steps": "not provided",
                      "environment": "not provided"
                    }
[HANDOFF] Passing draft to Triage Agent as JSON...
[HANDOFF] Checked: valid JSON with all 5 fields ✓
[AGENT 2: Triage]   Reviewing draft...
[AGENT 2: Triage]   Priority: HIGH ("crash" reported)
[AGENT 2: Triage]   Missing info flagged: "steps to reproduce", "device / browser", "file size tested"
[FINAL OUTPUT] Structured, triaged bug report ready for a human.

    ✅ HIGH, rightly: "crash" is a HIGH word. Triage also asks for the 3 things the report doesn't say: how to make it happen, which device, and how big the file was.

The lesson: each agent can only be as good as its own rules — and a mistake in one gets passed to the next. Real AI agents understand far more than a word list, but they make mistakes too, and the handoff is where those mistakes travel.

What a real AI did

On this page, both agents are simple rules, so the Drafter always fills in the form perfectly. A real AI might not: it could add chatty words around its JSON, or leave out a box. Then the JSON check stops the handoff with [HANDOFF FAILED], and the broken form never reaches Triage. So what really happens when two real AIs do this job? Here's one real run.

📅 A real run in the terminal (with --key) on 26 September 2026, using gpt-oss-20b, run by Groq. It's saved here, because this page never talks to an AI. A real AI can answer differently every time.

Bug report: When I click "Save" the page says: Error "null" -- and then the app freezes. Also the logo looks weird.

Agent 1, the Drafter (a real AI), sent back:

{"title":"Save button triggers null error and application freeze, logo distortion","description":"When the user clicks the 'Save' button, the page displays an error message containing \"null\" and subsequently freezes. Additionally, the application’s logo appears distorted.","severity":"unknown","steps":["Navigate to the relevant page in the application.","Click the 'Save' button.","Observe the error message that reads \"null\" and the application freezing.","Notice the logo appears distorted or incorrect."],"environment":"not provided"}

The handoff check, run live on that reply in your browser:

✓ Valid JSON with all 5 fields — passed. The form goes on to Triage.

Agent 2, Triage (a real AI), said:

Priority: HIGH, app freezes on critical action causing data loss risk.
Missing: environment
  • ✅ Good work: it turned a messy sentence into a clear title and description, and Triage asked which device was used.
  • ❌ Made-up steps. The report gives no steps, and the Drafter was told to write "not provided" — instead it invented 4 steps, like "Navigate to the relevant page in the application."
  • ❌ A made-up risk. Triage says "data loss risk", but nobody mentioned losing anything.
  • ❌ And the check let it all through. It only makes sure the 5 boxes are there. It didn't notice that "steps" came back as a list instead of text — and it can't tell a true step from an invented one.

The lesson: a strict format catches a broken form — not wrong information. Real AI agents write far better reports than simple rules, but they can make things up, and the next agent passes it on as fact. That's why real systems still have a person check anything important.
